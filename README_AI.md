# README_AI — STANDARDS

Required context for AI agents working in any **Breeze-On** repository.

## Mandate

1. **Follow org STANDARDS** — this repository (`Breeze-On/STANDARDS`) is the source of truth for process and technical conventions.
2. **Update documentation when you change reality** — if a task changes behavior, architecture, setup, or product scope, update the affected `README.md`, `README_AI.md`, and/or STANDARDS docs in the same change set.
3. **Current state only** — documentation describes what exists now. Do not document planned, speculative, or aspirational work as fact.
4. **Do not fork standards into product repos** — link here; keep product `README_AI.md` files thin and product-specific.

## How to use

Before planning or implementing in a Breeze On repo:

1. Read this file and [`docs/documentation.md`](docs/documentation.md).
2. Read any other STANDARDS docs relevant to the task (naming, engineering, UI).
3. Read that product repo’s `README_AI.md` for local scope.
4. Apply standards; if a standard is missing for something you introduce, add it to STANDARDS (current-state) rather than inventing a one-off convention.
