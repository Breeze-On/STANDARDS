# UI — Localization (culture + timezone + resources)

Current reality for language / timezone preferences and per-application UI string resources. Related: [shell.md](shell.md) (Settings), [forms.md](forms.md) (`BoDropDownList`), [overview.md](overview.md).

## Per-application resource library (locked — hard standard)

1. **Each application owns its own resource library** (`.resx` + culture satellites). Examples: SHARED-UI Gallery uses `BoUi` in `BreezeOn.UI`; ADM (when localized) will introduce its **own** resource set in `SYSTEM-ADMIN-ADM` — it must **not** reuse Gallery/`BoUi` keys as a shared glossary.
2. **Never hardcode user-visible labels** in Razor/C# (page titles, nav labels, tab/section/field labels, buttons, dialog copy, aria-labels meant for users, etc.). Always resolve through a Resource key via a locale-aware localizer.
3. **Do not share string catalogs across applications** for the same conceptual word. Even common words such as “Close” must live in **that app’s** resources so each product/company can choose its own wording.
4. `BreezeOn.UI`’s `BoUi.resx` / `BoUi.fr.resx` are the resource library for the **SHARED-UI Gallery host** (and chrome it demos). They are **not** an org-wide translation pack for other apps.

## Preferences (locked)

| Concern | Standard |
| --- | --- |
| Service | `IBoLocaleService` (scoped); restore via `BoLocaleBootstrap` inside `BoProviders` |
| Language options | `en` (English), `fr` (Français) — fixed catalog |
| Timezone options | Curated IANA list (Canada-first + UTC + common peers); default `America/Toronto` |
| Apply behavior | Settings DDLs update the service **immediately** (no separate Save); Close only dismisses |
| Formatting culture | `en` → `en-CA`, `fr` → `fr-CA` on the circuit |

### Cookie contract

| Cookie | Values | Default if missing/invalid |
| --- | --- | --- |
| `bo-culture` | `en` \| `fr` (lowercase) | `en` |
| `bo-timezone` | IANA id (e.g. `America/Toronto`) | `America/Toronto` |

Shared attributes (same family as `bo-theme-mode`): `Path=/`; `Max-Age≈31536000` (1 year); `SameSite=Lax`; `Secure` when HTTPS; `HttpOnly=false` (JS-readable for Interactive Server). Hosts load `_content/BreezeOn.UI/js/bo-locale.js` early (gallery `App.razor`).

## Resource foundation (SHARED-UI / Gallery — current)

- Library resources: `Resources/BoUi.resx` (default English) + `Resources/BoUi.fr.resx` (satellite `fr`)
- Resolve strings via **`IBoUiLocalizer`**, which reads `IBoLocaleService.Culture` explicitly so language switches apply **immediately without a full page reload** (ambient `IStringLocalizer` / request culture alone is not enough on Interactive Server)
- Marker type: `BreezeOn.UI.Resources.BoUi`
- **Shipped:** Gallery + shell chrome user-visible strings (nav, header tabs, Theme/Components/Home, Settings, Profile Sign out, dialogs, aria labels, etc.)
- Layouts/pages that show localized text should subscribe to `IBoLocaleService.Changed` and re-render

### Host requirements

1. `AddBreezeOnUI()` (registers locale + `IBoUiLocalizer`)
2. Configure supported cultures `en` / `fr` (`RequestLocalizationOptions`) and `UseRequestLocalization()`
3. Render `BoProviders` (locale bootstrap) and load `bo-locale.js` early

## Settings composition (locked)

Dialog has **no** popup header title or × button. Content:

1. One `BoSectionMain` titled **Settings** (localized)
2. `BoRow` → `BoDropDownList` Language (`FieldKey=Language`)
3. `BoRow` → `BoDropDownList` Timezone (`FieldKey=Timezone`)
4. Footer Close button (and backdrop click) dismisses

## Explicit non-goals (not current reality)

- Azure AD / Entra profile photo
- Real Sign out / Identity / ADM wiring
- Per-user DB preference store
- ADM’s own resource library (until ADM ships localized UI)
- Localizing framework reconnect modal static HTML (gallery host template)
